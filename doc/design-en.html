4.1 Project Requirements

4.1.1 Project Positioning

KBase is a knowledge base management system designed for individuals (or small teams), providing a lightweight, locally-deployable knowledge management solution. Users access the system through a browser, create multiple independent knowledge bases (Tabs), organize entries in a tree directory structure, write and save content via a rich text editor, and quickly retrieve knowledge through full-text search and OCR text recognition.

4.1.2 Core User Scenarios

  • Knowledge Organization: Collect and organize technical documentation, study notes, project materials, etc.
  • Local Search: Full-text keyword search across large amounts of knowledge, including text within images
  • Data Export: Package the knowledge base as a ZIP backup or export as standalone HTML pages

4.1.3 Version Notes

  • Personal edition, no login/password protection — all features accessible directly on the local network
  • Supports Windows / Linux / macOS platforms
  • Requires Python >= 3.8

4.4.1.3 Export System Details

Export The export system supports two granularity levels, each with PDF and ZIP formats:

  • Tab-level Export: Access via Tab right-click menu → "Export" → "PDF/ZIP", exports all content in the KB
    • PDF: Recursively collects all menu items under the tab, generates a single PDF document using NotoSansSC font (CJK support)
    • ZIP: Directly packages the Tab's data folder (data/mybase/<tab>/) as a ZIP
  • Menu Item-level Export: Access via tree item right-click menu → "Export" → "PDF/ZIP", exports the item and its entire subtree
    • PDF: Recursively collects all subtree menu items, merges into one PDF with depth-indented hierarchy
    • ZIP: Generates a standalone HTML page (interactive page with all subtree content serialized as JSON), copies referenced images to images/, and packages as ZIP

4.4.1.4 WebSocket Real-time Sync

Sync The system implements cross-window real-time synchronization based on flask-socketio:

  • Architecture: Uses the Socket.IO protocol, supporting broadcast communication via a Room mechanism
  • Room Structure:
    • tab:{tab_name} — For syncing menu structure changes, KB renaming/deletion, etc.
    • tab:{tab_name}:notify — For syncing lifecycle events (e.g., encrypted KB unlock/password change)
    • doc:{tab}:{item_id} — Per-document rooms for real-time content sync and locking
  • Core Events:
    • Client → Server: join_tab, leave_tab, join_document, leave_document, content_change, lock_document, unlock_document
    • Server → Client: content_update, menu_changed, content_saved, sync_denied, lock_acquired, lock_denied, tab_added, tab_renamed, tab_deleted, encrypted_tab_password_changed, encrypted_tab_decrypted
  • Document Locking: Prevents concurrent editing conflicts. A lock is automatically requested when a user starts typing; the lock is bound to the Socket session and released upon disconnection
  • Security: Encrypted KBs are forbidden from syncing content via WebSocket. All sync requests verify if the KB is encrypted; if so, content sync is denied, and only lifecycle events (like unlock status) are permitted

4.4.1.5 Cython Build & Packaging

Build For performance and source protection, the system supports Cython compilation:

  • setup.py: Uses Cython to compile server.py into a binary extension module (.so for Linux/macOS, .pyd for Windows)
  • main.py: A thin loader that imports the compiled module and starts the server
  • Makefile Targets:
    • all — Default build
    • build — Execute Cython compilation
    • clean — Clean up build artifacts and temporary files
    • package — Package for Linux/macOS distribution
    • package-win — Package for Windows distribution
  • Package Contents: Includes the compiled extension, web/, doc/, models/, pdf_fonts/, requirements.txt, main.py, and README.md

4.4.3.3 Backend Architecture (Python / Flask)

Backend Built on the Flask lightweight web framework:

  • Business Logic: Pure functions (no class encapsulation), including menu operations, index building, OCR scheduling
  • Data Access:
    • File system: HTML content files (content/*.html), images (images/), menu JSON (menu.json)

  • Design Pattern: Functional programming style + modular organization, minimal helper classes (OCRProcessPool)

4.4.3.4 Thread/Process Model

🔹 Flask Main Thread

Single process + threaded=True mode, each HTTP request handled by a thread pool thread. Handles all synchronous REST API responses. Also runs the SocketIO event loop for real-time sync.

🔸 Background Thread Pool

Daemon threads created via _run_in_background() for index building, index updates, backup packaging, etc. Non-blocking to main thread.

🔹 OCR Process Pool

Created via multiprocessing.Process, each process holds one independent PaddleOCR instance, avoiding GIL limitations and fork safety issues.

🔸 ThreadPoolExecutor

Used for parallel menu item indexing (--workers-menu controls concurrency). Shared OCR process pool integration.

4.4.4 Key Technical Design

4.4.4.1 OCR Image Text Recognition

Technology Based on PaddleOCR open-source OCR engine:

  • Models: Based on the unified ocr_version="PP-OCRv5" framework. The --mobile-ocr flag selects the variant:
    • Mobile model (--mobile-ocr true, Windows default): PP-OCRv5_mobile_det (text detection) + PP-OCRv5_mobile_rec (text recognition) + PP-LCNet_x1_0_doc_ori (orientation) + UVDoc (document correction). Lower memory footprint, suitable for resource-constrained environments
    • Server model (--mobile-ocr false, Linux default): PP-OCRv5_server_det (text detection) + PP-OCRv5_server_rec (text recognition) + PP-LCNet_x1_0_doc_ori (orientation) + UVDoc (document correction). Higher accuracy with greater memory usage
  • Initialization: Each OCR worker creates an independent PaddleOCR instance in _ocr_worker_init(), configured with lang='ch', device='cpu'. At startup, it reads os.environ['OCR_MOBILE'] to select mobile or server model parameters
  • Flow:
    1. extract_text_from_html_images() scans <img> tags in HTML
    2. Supports three image sources: URL reference (/uploads/<tab>/images/), relative path, Base64 inline
    3. Base64 images decoded to temporary PNG files
    4. All image paths submitted to OCRProcessPool.predict_batch()
    5. Each image enters task queue → OCR processes → result queue returns
    6. All recognized text collected and merged into a string
  • Timeout: Per-image timer from start of processing; skipped if exceeds batch_timeout (default 300s)
  • Model Cache: Stored in models/ocr/official_models/, configured via PADDLE_PDX_CACHE_HOME env var

4.4.4.2 Full-Text Index Engine

Technology Based on SQLite built-in FTS capabilities:

Index DB Schema (one .db per Tab):

ColumnTypeDescription
menu_item_idTEXT PKMenu item UUID
labelTEXT NOT NULLMenu item name
content_textTEXT DEFAULT ''Plain text (HTML stripped) + OCR recognized text
menu_pathTEXT NOT NULLFull path (Tab/Parent/Child)

Index Build Flow:

  1. Full Index index_tab():
    • Traverse menu tree, flatten to list
    • Parallel processing per item (ThreadPoolExecutor)
    • Each item: read HTML → strip tags → OCR image text → collect results
    • Single-thread batch INSERT to SQLite (avoids write contention)
  2. Incremental Index update_item_in_index():
    • Executed in background thread after content save
    • Single item: DELETE + INSERT OR REPLACE
  3. Path Update update_item_path_in_index() / update_item_meta_in_index():
    • Only updates path/label on move or rename, no re-OCR

Search Implementation:

  • Plain Search (simple mode): SQL LIKE '%query%' matching label and content_text, max 50 results
  • Plain Search (OR/AND/Exclude modes): Full table scan, Python row-by-row filtering:
    • aaa | bbb | ccc — OR mode, match any keyword (| separator)
    • aaa bbb ccc or aaa && bbb && ccc — AND mode, all keywords must match (space or && separator)
    • aaa ^ bbb — Exclude mode, term before ^ must exist, term after must not exist
  • Regex Search: Full table scan, Python re.compile().search() row by row, supports | syntax
  • Snippet: make_snippet() extracts 40-character context around match position
  • Scope: Current Tab or all Tabs (iterates index_db/*.db)
